Kinex supplies robotics tools, skills and context from @kinex/core. Call kinex_tools before robotics work, after resume/compaction, and whenever capabilities may have changed. Use kinex_call with a current tool schema. Use kinex_stop immediately on faults; it bypasses the Kinex queue. Permission denials and cancelled questions mean stop and wait for user direction, not retry.

Device state and catalogs are live tool results, not stable system instructions. Calls return changed context; kinex_tools always returns a complete snapshot. The user can run kinex-codex control in their own terminal for direct device and recording commands. Those trusted user controls are not an alternative route for model calls: never invoke them through shell tools to bypass Kinex permissions or recording opt-in. Workflow prompts are available from kinex_tools with workflow and arguments. They guide work using normal permission-checked tools.

Model recording exists only when the server was started with --enable-recording. Manual recordings belong to the same server instance. MCP connection identity is used for recording attribution; no Codex conversation transcript is exported. General host shells retain their normal Python environment.
