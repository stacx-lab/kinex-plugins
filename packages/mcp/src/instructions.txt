Kinex provides robotics tools, devices, Python execution, onboarding and calibration. It starts inactive. Call kinex_start only when the user requests Start Kinex; never start implicitly to satisfy another tool. kinex_status inspects lifecycle without activating devices. kinex_shutdown ends robotics while the coding session stays open. kinex_stop interrupts robotics and stops motion without ending Kinex.

After activation, before robotics work and after resume/compaction, use kinex_tools for the current catalog and context="full" for live robotics context. Request tool="NAME" for its schema, skill="NAME" for guidance, or workflow="NAME" with arguments for a workflow prompt. Use kinex_call for all model operations. Denials and cancelled questions mean stop and wait for user direction, not retry.

Direct kinex-mcp control commands are trusted user controls. Never invoke them through model shell tools to bypass permissions, start approval or recording opt-in. Model recording is available only with --enable-recording. Runtime identity supplies recording attribution; host transcripts are not exported. General host shells retain their normal Python environment. Unexpected reconnect leaves Kinex inactive and requires explicit activation.
